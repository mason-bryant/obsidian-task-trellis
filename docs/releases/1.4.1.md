# Task Trellis 1.4.1

## Reinstalling keeps your boards and settings

Uninstalling a plugin deletes its settings, and Obsidian Sync deletes them on your other devices too. After a reinstall, Task Trellis looked for boards in its default folder, **Task Trellis**. If yours were somewhere else, it said you had none and offered templates. Your board notes were never affected.

- **A copy of the settings:** every time they're saved, Task Trellis also writes a copy to `Task Trellis recovery/plugin-settings.json`, outside its own folder. After a reinstall it restores that copy and says so once.
- **Finding your boards:** with no settings and no copy, Task Trellis looks for board notes elsewhere. If they're all in one folder, that becomes the boards folder, with a notice. If they're in several, the boards sidebar offers each, as **Use ‹folder›**, instead of the templates.
- **Settings changed by Sync** are taken up as soon as they arrive. Before, a device with old settings in memory could save them back over newer ones from another device.

You never need to uninstall Task Trellis to update it. See [My boards disappeared after reinstalling](https://github.com/mason-bryant/obsidian-task-trellis/blob/1.4.1/docs/troubleshooting.md#my-boards-disappeared-after-reinstalling).

## Notes opened from a board's tab open in the editor

With a board showing in a tab, opening another note in that same tab, from the file explorer or a link, showed the note as a board. It also added a `slug` property to the note. Now the note opens in the editor, untouched, and another board still opens as a board. If your notes gained a `slug:` line this way, you can delete it; only board notes use it. Thanks to the user who reported this in [issue 60](https://github.com/mason-bryant/obsidian-task-trellis/issues/60).

## Compatibility

Requires Obsidian **1.13.7 or later**. Nothing to migrate: existing settings, boards and tasks are kept.

- **The settings copy** is written the first time the settings are saved after updating, such as when you collapse a row. It's a small JSON file in the **Task Trellis recovery** folder, which rename recovery already uses, and it holds only the plugin settings. It syncs if your sync service includes JSON files. To reset the settings with a reinstall, delete it first.
- **Earlier releases** ignore the copy.

## Validation

- **Automated:** 1020 application tests and 8 shortcut tests, lint, TypeScript checking, the harness build and packaging, locally and in CI.
- **Browser preview (the harness):** the boards sidebar offering folders that hold boards, and choosing one.
- **Native macOS, Obsidian 1.15.0,** in a disposable vault with boards in a folder other than the default, using Obsidian's own uninstall and enable, and a real click on the sidebar's folder button:
  - Reinstalling with the copy restored the settings, with a notice; reloading without saving restored them again without a second notice.
  - Reinstalling without the copy made the one folder holding boards the boards folder, with a notice, as did a first install into a vault that already had boards there.
  - With boards in two folders, the sidebar came forward offering both, and choosing one brought its boards back.
  - Obsidian's error log was clean.
- **Notes in a board's tab, on Obsidian 1.15.0:** reproduced first on the 1.4.1 code without the fix. A task note opened in a board's tab, as the file explorer opens it, showed as a board and gained `slug: personal`. With the fix, it opened in the editor unchanged, Back returned to the board, and another board opened in the same tab still showed as a board.
- **Before tagging:** the same code was installed in the maintainer's own vault, where it loaded every board with its settings intact.
- **Not tested:**
  - Sync starting the settings reload. Obsidian calls it only when Sync changes the settings file, so it was tested by calling it directly.
  - A real reinstall on a phone with Sync, and phones and iPad generally.
  - Obsidian 1.13.7, Windows, where the board's tab problem was reported, and Linux.
