## Native macOS Obsidian 1.13.7 (installer 1.8.10)

All checks used the disposable "Task Trellis Readiness Test" vault with synthetic tasks. Only Task Trellis was installed there, so Tasks and Templater were not loaded.

- **Upgrade from 0.1.16:** the vault had last run 0.1.16. With the candidate installed, its boards, settings and the boards sidebar opened normally.
- **Desktop subtask reordering with a real mouse:** dragging the Clean brushes row above First coat showed the dragged row following the pointer and an insertion marker. The note was rewritten in the new order, the Undo bar said Subtask reordered, and Undo restored the exact original lines. This closes the native mouse-drop gap from the [October 29 report](subtask-reorder-2026-10-29.md).
- **Keyboard:** Tab reached a subtask row, and Alt+Down moved it, kept focus on it and offered Undo. Enter opened the source note in the pop-up editor with the line highlighted. Escape closed the pop-up and returned focus to the row. Undo restored the order.
- **2,000 cards:** a board over 20 synthetic notes (2,000 tasks, 200 subtasks) was fully drawn within 1.5 s of opening, and scrolling was smooth.
- **Obsidian internals:**
  - Opening a board note through an `obsidian://` link showed it as a board (the `setViewState` patch).
  - Turning the plugin off kept the open board tab as a placeholder; turning it on restored the board in place (the view registry).
  - Task Trellis: Add task opened the New task prompt and added the task to a newly created daily note (the Daily notes internals).
  - The source-note pop-up opened, closed and returned focus to the card.
- **Mixed versions:** board settings saved by the candidate (`label-shape`, `hide-completed-subtasks`) were then read by 0.1.16, which rendered the board. A settings save from 0.1.16 wrote only its own change (`limit-done: false`) and kept the newer keys. The candidate was reinstalled afterwards.
- **Incident:** a mis-aimed click opened the pop-up editor, and four Tab presses meant for the board added a line of tabs to the end of a synthetic note. The line was removed.

## Native macOS Obsidian 1.14.5 (installer 1.14.5), with Tasks and Templater

The same vault, after updating Obsidian to the current release and installing Tasks 8.6.0 and Templater 2.26.0 from their GitHub releases. Tasks was set to add created dates. Templater had a folder template for `Tasks/`.

- **Obsidian internals:** opening a board note in a new tab showed it as a board. Turning the plugin off with two boards open kept both tabs as boards, and turning it on restored them with no errors. Adding a task to the default destination, Daily notes, wrote it to today's note.
- **2,000 tasks:** a full redraw of the load board took 408–495 ms over five runs, drawing 952 cards with the Later row (1,048 cards) collapsed.
- **Tasks:** every task Task Trellis added carried `➕ 2026-10-30`. Completing a task through Tasks moved its tags before its date fields (`#tt/…` then `⏫ ➕ 📅 ✅`), which is how Tasks writes a line; the board read it correctly.
- **Templater:** see [Findings](#findings). A note Task Trellis creates doesn't get its folder template.

## Command line

Run with `/Applications/Obsidian.app/Contents/MacOS/obsidian-cli` against the test vault, with Templater on unless noted.

- `boards`, `show` (JSON and text), `task`, `add` (with subtasks, labels, a due date, a new or existing note and heading, `dry-run` and `request-id`), `set` (text with priority, and a stale `expect` that was refused), `move` (with `dry-run`), `undo`, `complete` and `bulk` all returned the documented results, and the notes matched.
- Retrying an add with the same `request-id` added nothing and returned `duplicate: true`.
- An add into a note that didn't exist created it with the heading and task, with subtasks indented under the task.
- **The `obsidian` binary loses results:** the same commands run as `obsidian` with the app's `Contents/MacOS` folder on PATH, which runs the app binary `Obsidian` because macOS file names ignore case, often printed nothing, though the change was made. An `eval` that resolves after 50 ms or more printed nothing through `obsidian` and printed correctly through `obsidian-cli`, so it's the binary, not Task Trellis. See [Findings](#findings).

## Findings

Open, in the candidate build unless noted:

1. **A 2,000-task board restarts Obsidian on iPhone.** It reproduced twice, and a 500-task board restarted once while notes were syncing. The same board at phone width in desktop Obsidian's mobile mode drew 952 cards with a 40 MB JavaScript heap and no errors, so the cause is probably the iOS web view running out of memory. That isn't confirmed. The board draws every open card, about 56,000 elements and 7,000 icons for 952 cards. A 1,000-task board didn't sync in time, so the size at which it starts is unknown.
2. **Reorder and Undo results aren't spoken.** "Subtask reordered" and "Backlog moved to position 1 of 3." appeared on screen but VoiceOver never said them. A probe in the same window showed why: VoiceOver spoke a status region that already existed when its text changed, but not one inserted with its text, nor one filled straight after insertion. The board's Undo status and the settings reorder status are both rebuilt on every redraw. The bulk selection count and filter warnings use the same pattern.
3. **Obsidian notices aren't spoken.** Obsidian's notice container has no live-region role, so errors and warnings shown with `Notice`, such as "added to 2026-10-30, but this board's filters hide tasks from that note", are silent. The accessibility rules ask for errors that need attention to be alerts.
4. **The composer's check button drops focus.** Pressing the check with the keyboard saves the task, but the button is disabled while saving, so focus falls to the page and nothing is spoken. Enter in the text box keeps focus there.
5. **Column separators are read as "vertical splitter 240 pixels".** Their `aria-label` (Resize ‹column› column) isn't spoken; VO+F3 also gave only the value.
6. **"Add task" doesn't say which cell.** Every cell's button reads "Add task", with no column or row.
7. **Templater folder templates don't apply to notes Task Trellis creates.** Task Trellis creates the note empty and writes the task at once; Templater only fills a note that is still empty after a short delay, so `Tasks/Kitchen project.md` got the heading and task but none of `Templates/Project.md`.
8. **Appending without a heading leaves a blank line before each task,** so tasks added to a daily note one at a time are separated by empty lines.
9. **`docs/cli.md` should point macOS users at `obsidian-cli`,** or warn that `obsidian` can print nothing for commands that take more than a moment.
